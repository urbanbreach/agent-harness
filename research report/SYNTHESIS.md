# ULW-Research Synthesis: Harness visual parity with Grok Build

STATUS: final

## Executive summary

Harness should adopt Grok Build's presentation grammar, not its identity or
architecture wholesale. Ten bounded changes close the visual, spatial,
interaction, motion, and polish gap while preserving Harness branding, exact
anchors, reduced motion, palette ranking, operator surfaces, and event-sourced
runtime authority.

## Findings by theme

### P0

1. Full-surface dashboard plus exact return anchor.
2. Dense transcript folding and response navigation; pin reserve only after a
   failing reproduction.
3. Rich tables, citations, streaming fences, and production OSC-8 propagation.
4. Visible composer modes and explicit submission intents.
5. Truthful typed disconnect/reconnect/reload states.
6. Emulator-backed PTY visual evidence.

### P1

1. Slash argument completeness and highlighting without weakening palette
   ranking.
2. Reusable modal chrome while preserving stronger Harness affordances.
3. Harness-branded startup motion with reduced-motion fallback.
4. Live resize debounce, follow dimming, and terminal-safe glyph routing.

## Codebase findings

- Harness's dashboard return model already declares an anchor, but entry stores
  `None`.
- Harness already folds at the model/projection layer; a second fold authority
  would be a defect.
- Harness owns OSC-8 code and tests, but production rich rendering drops
  destinations.
- Harness already has persistent multiline state; the parity gap is visibility
  and submission semantics.
- Request retry is not live-stream reconnect.
- TestBackend and reply-less VT parsing are not emulator-grade terminal proof.

## Verified claims

The report publishes only supported or explicitly caveated claims. Refuted
claims include absent aggregation, absent OSC-8, missing multiline state,
scheduler drift, larger Grok close targets, quantization drift, weak Harness
anchors, and automatically superior estimated off-screen layout.
