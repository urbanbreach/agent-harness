# UI polish against Grok Build — 15 September 2026

Implemented the remaining composer interaction gaps and an expanded-command error
styling regression. This builds on the existing [presentation parity](grok-build-parity-implementation.md)
and [chat/tool parity](chat-tool-render-parity.md), using their renderers, editing
helpers, theme roles and QA tools. No dependencies were added.

Open the [xterm.js comparison gallery](../.omo/evidence/ui-polish-20260915/index.html)
for interaction evidence and selectable transcript animation frames.
The captures and logs are local, ignored artifacts; the implementation, regression
tests and capture drivers are source files.

## Findings and implementation

| Area | Finding and result |
| --- | --- |
| Composer selection | Keyboard selection changed the buffer state but was invisible in the main composer. Selected graphemes now use reverse video, including across wrapped rows. |
| Pointer editing | Clicking only focused the composer. Clicking now places the caret; dragging and Shift-click extend selection using the same measured viewport as painting. Resize, modal ownership, replay and keyboard input invalidate pending drags. |
| Caret position | Rendering sometimes preferred a stale editor cursor when the text itself had not changed. It now follows the active prompt cursor, retaining the existing collapsed-paste mapping. |
| Unicode | Scalar-based wrapping, movement and deletion could split combining marks or emoji sequences. These paths now use the installed grapheme implementation; CJK and emoji retain their display-cell widths. |
| File mentions | The main bordered composer bypassed the existing mention styling. It now shares the styled-line renderer and keeps mention emphasis when selecting text. |
| Composer chrome | Multiline mode appeared twice. There is now one `MULTILINE` badge; metadata fit uses display width. |
| Dashboard | A single participant now reads “1 agent”. |
| Command errors | An error summary was treated as ordinary terminal output. Failed commands now distinguish actual stdout/stderr from the error message, preserving the latter's red foreground and surrounding background. |
| QA | The compact multiline journey checks each submission while visible and confirms the cancellation boundary before replacement. The chat comparator now filters blank cells explicitly, matching its documented scope even with full-cell xterm snapshots. |

The existing startup, dashboard, command palette, settings, tool disclosure,
streaming Markdown and animation implementations already cover the main reference
surfaces. This pass exercised them alongside the changed composer. Animations keep
titles and geometry fixed, and reduced motion remains static.

## Comparison and remaining differences

Reference: the local import of [xAI's Grok Build](https://github.com/xai-org/grok-build),
`SOURCE_REV` **eb4a894da8fb7bcd8d8f398a9d909a7868a4fcf1**. Its production
`EntryRenderer`, `ScrollbackState` and `ScrollbackPane` are driven by
`scripts/qa/fixtures/grok-chat-capture.rs`. A fresh offline build reproduced all
252 reference ANSI frames byte for byte; see the [rebuild receipt](../.omo/evidence/ui-polish-20260915/reference/rebuild-verification.json).

The final matrix contains **337 Harness frames and 252 reference frames** rendered
through Chromium and xterm.js 6.0.0. Transcript samples cover 14 scenes, three
sizes (40×24, 80×24, 120×40), three times (0/330/660 ms), and both motion settings.

The [cell audit](../.omo/evidence/ui-polish-20260915/comparison-audit.json) compares
**4,095 nonblank cells in 42 normal-motion pairs at 120×40**. Text, widths,
positions, backgrounds and color modes match throughout. **37 pairs are exact**;
five have **seven animated rail cells differing by one RGB level**. This is
consistent with Harness sampling 328 ms on its 4 ms clock while the reference
uses tick 10 at 330 ms. The strict equality comparator still rejects these five
pairs; its tolerance was not relaxed. All **42 scene/size reduced-motion cases**
remain identical across time.

The comparison translates Harness's transcript origin by (-2,-3) and excludes
shell chrome. It does not establish whole-application pixel identity. Smaller
terminals have different available transcript heights. The reference's reduced
fixtures freeze the tick; Harness exercises its actual accessibility policy.

Backend-dependent differences remain as described in the existing
[authority mapping](grok-build-parity-implementation.md#authority-mapping-and-comparison-limits):
provider-plan approval, commercial credits, marketplace installation, ACP and
cross-session ownership need corresponding backend contracts. Existing controls
continue to represent actual Harness capabilities.

## Reproduce the changed behavior

```bash
cargo nextest run --profile ci -p harness-tui --all-features
scripts/test-lanes.sh simulation --artifact-dir /tmp/harness-ui-simulation
env -u NO_COLOR TERM=xterm-256color COLORTERM=truecolor \
  HARNESS_PARITY_RENDER_ARTIFACT_DIR=/tmp/harness-ui-frames \
  cargo nextest run --profile ci -p harness-tui --all-features \
  -E 'test(grok_parity_surfaces) | test(chat_and_tool)'
node scripts/qa/render-recorded-frames.mjs \
  /tmp/harness-ui-frames .omo/evidence/ui-check
```

The composer regression exercises actual keys, paste, click/drag, selection,
wrapped Unicode, modal ownership and resize at three terminal sizes. Existing
public rendering tests now also assert that expanded failures retain error styling.
