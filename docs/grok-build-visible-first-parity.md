## Execution strategy
### Parallel execution waves
> Target 5-8 todos per wave. Fewer than 3 (except the final) means you under-split.
- Every coding worker loads `karpathy-guidelines` and `programming`; Rust writers also load `rust-best-practices`; async runtime owners add `rust-async-patterns`; visual milestone reviewers load `visual-qa`. Workers use `apply_patch`, never broad rewrite scripts.
- The lead creates a reservation manifest before dispatch. A writer receives exact exclusive paths and may not touch anything else. The lead rejects intersecting reservations before spawn and, after the wave, verifies that all paths outside the union are byte-identical to the wave preimage.
- Editing lanes run concurrently, but build/test commands use one FIFO Cargo lease. `Cargo.lock`, workspace/crate `Cargo.toml` files, `crates/harness-tui/src/{app,ui,lib}.rs`, top-level overlay/keybinding registries, shared test support, lane scripts, and public manifests are serial-integrator roots. `theme.rs` and `layout.rs` each have one dedicated owner; no other concurrent lane may touch them.
- Capture/browser/native-display resources are singleton leases. Each wave has an isolated evidence root; only its integrator may invoke capture scripts.
- Final-candidate contract: Todo 33 copies the final `target` binary to a content-addressed path under its evidence root, records its SHA-256, makes it read-only, and adds one fail-closed `HARNESS_CANDIDATE_BIN` + `HARNESS_CANDIDATE_SHA256` contract to every Wave 5 lane. With `HARNESS_REQUIRE_SEALED_CANDIDATE=1`, product invocations must execute that absolute regular-file path directly; `cargo nextest` may build validator/test executables but no receipt may use `CARGO_BIN_EXE_harness`, `cargo run`, newest-`target/debug/deps` selection, or another workspace binary as candidate evidence.
