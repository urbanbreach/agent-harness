# Compaction motion evidence

Regenerate every lane from the repository root:

```sh
CARGO_TARGET_DIR=/home/urbanbreach/.cache/harness-targets/Captures cargo build -p harness
CARGO_TARGET_DIR=/home/urbanbreach/.cache/harness-targets/Captures node scripts/qa/capture-compaction-motion.mjs docs/evidence/compaction-motion
```

The script needs the QA npm dependencies, Chromium, Adwaita Mono, a real PTY (`script`), and ffmpeg. It uses isolated temporary workspaces and a local scripted provider; no external model request is made. Each lane can also run alone: `node scripts/qa/lib/compaction-surfaces.mjs /tmp/harness-xterm-surfaces` for the typed surfaces and `node scripts/qa/lib/compaction-live-capture.mjs <output> <target dir>` for the real coordinator.

There are three lanes:

- Motion: typed durable and live events on a fixed clock, one pass per method (`frames/motion-*`, `frames/reduced-*`).
- Surfaces: a hand-written conversation with key presses and command outcomes, for the rows, history modes, footer, pending band and threshold editor (`frames/surface-*`).
- Real coordinator: the actual `harness tui` binary against a local scripted provider (`real/`).

## Fixed-clock presentation lane

`synthetic-events.json` supplies typed durable and live events to the real AppState renderer through a PTY and xterm.js. The fixture advances the injected clock, paints a frame, and acknowledges it before the browser captures it. This keeps screenshot latency from moving a capture into the next phase. Test-harness output is redirected away from the terminal; the renderer writes directly to its PTY.

`manifest.json` records each PNG, method, phase, injected `at_ms`, wall-clock capture time, expected screen text, and any assertion failures. Budget values and thumbnail bitmaps in this lane are deliberate visual fixtures, not measured conversation sizes. `motion.ansi` and `reduced.ansi` retain the terminal output. `compaction-motion.gif` is an eight-frame-per-second montage generated by ffmpeg.

Every card and loader in this lane carries the lifecycle label ("Compacting context…" for manual passes, with the interrupt key) and a `[stop]` control while a pass runs. The expanded surface makes the context itself the hero: two full-height block rows with eighth-cell partition boundaries, a full-height threshold marker and value, progress-driven dissolution and lifting particles, and a matching colored legend. Soft compaction uses seven rows; methods with a filmstrip or other flourish use eleven. Short terminals retain the eight-row presentation, and narrow/very short terminals retain three rows. Only the live surface, the fresh divider, and its small context breadcrumb accent need motion; archived transcript rows remain settled and readable. The header usage denominator is the context window before and after maintenance; the threshold is a separate bar marker.

The collapsed-history preference is on in this lane, so each new summary divider replaces the previous one. A shake divider stays beside it, because a prune is not a summary. The earlier turns stay in the journal.

## Fixed-clock surfaces lane

`surface-events.json` is one conversation of four turns plus later passes. It holds typed durable and live events, key presses (`key`), typed text (`text`) and manual command outcomes (`outcome`). The driver in `crates/harness-tui/tests/support/manual_compaction_capture.rs` sends keys through `AppState::handle_key` and outcomes through `apply_compaction_command_outcome`, draws twice per captured frame so the viewport settles, and uses the same injected clock as the motion lane. The shell has a 200K window, two mock models, and a project config under the isolated capture home, so the collapse preference and threshold editor write nothing outside the temporary directory. Token counts are visual fixtures.

`manifest.json` lists these under `surfaces.frames` with the expected screen text, text that must be absent, and the injected `at_ms`. Assertion failures are collected in `surfaces.failures` and fail the run. `surfaces.ansi` keeps the terminal output and `compaction-surfaces.gif` is a slideshow of the frames.

- Pending band: `26-pending-band-steering-then-after-yield` has a steering line and a follow-up queued while a pass runs, under `Steering` and `After yield`.

And a settled frame can be taller than the viewport, which is why the full-history toggle has a second frame scrolled to the first turns.

## Real coordinator lane

`real/` is captured from the actual `harness tui --scenario compaction_interactive` binary. A deterministic local provider streams an ordinary answer and structured compaction summaries. Real conversation content crosses the configured threshold; the coordinator emits the lifecycle events, maintenance stages, status updates and durable boundary. The scenario binds a settings file beside the session store so the model switcher can open the threshold editor.

- `real/automatic-live-card.png`: automatic soft compaction with the threshold reason, the lifecycle loader label and `[stop]`. The footer shows the auto icon, the usage and the gauge from the published status.
- `real/automatic-divider.png`: committed context boundary.
- `real/automatic-divider-and-answer.png`: the boundary followed by an answer that depends on the retained summary.
- `real/manual-compact.png` and `real/manual-shake.png`: command routing through the same coordinator session. A real `/compact` that succeeds adds only the new divider, because its outcome carries no message.
- `real/history-collapsed-default.png`, `history-full-after-toggle.png` and `summary-card-expanded.png`: the collapsed default, the full transcript after Ctrl+Alt+K (the older divider reads `5.1K→316`), and the newest card opened with Ctrl+Alt+O.
- `real/manual-outcome-warning.png`: a second `/compact` with nothing left to summarize.
- `real/pending-band-steering-then-after-yield.png`: steering and a follow-up queued during a real automatic pass, with the loader and `[stop]`. A real runtime warning row from the coordinator is visible above it.
- `real/auto-outcome-cancelled.png`: Ctrl+C during an automatic pass leaves a status row. `real/manual-loader-and-stop.png` and `real/manual-outcome-cancelled.png` show a manual `/compact` with its loader, then the cancelled error row.
- `real/model-switcher.png`, `threshold-editor-empty.png` and `threshold-editor-fixed-tokens.png`: Ctrl+T in the model switcher and a typed `f4000`.
- `real/notes-rollover-divider.png` and `notes-rollover-card-expanded.png` come from `--scenario compaction_notes_interactive`, which turns on `runtime.compaction.notes_windows` and keeps the real notes tools callable. The journal (`real/notes-events.jsonl`) holds a `session_compaction` with `details.kind` of `notes_rollover`.
- `real/frames/`, `real/coordinator-compaction.gif`, and `real/manifest.json`: timed frames, animation, and assertions. The manifest records the actual before/after totals and durable boundary sequences, and `surfaces` holds the expected screen text of every named frame above. The timed frames stop before the keyed surfaces start, because a background recorder slows the screenshots of fast passes.
- The copied journal and cleanup receipts in `real/` provide provenance for real coordinator events rather than synthetic event injection.

A PNG is taken between two reads of the screen text, and the run fails when the expected text is missing from either, so a frame cannot show a pass that moved on.

Not reachable in the real lane, and covered only by the surfaces lane: footer severities above normal and the armed and running speculation states (the scenario has async summaries off and a 64K window with a 5K threshold), a manual command done row with a message, and the pulse of the running icon. The real warning reads "Nothing to compact (session too small)".

## Runtime behavior and scope

`/compact [soft|remote|archive] [focus]`, `/handoff [focus]`, and `/shake [elide|images|thinking]` use typed intents. Archive mode rejects focus instructions. Submitted input during maintenance stays in a TUI-local queue with tags and attachments, shown under `Steering` and `After yield`; end-marker dispatch is ordered and admission failures restore the unsent remainder. Tagged or attached steering uses the existing ordinary-submit path, and skill expansion is not exposed by this TUI. Idle maintenance is governed independently by the idle settings, rechecks eligibility at the deadline, and is cancelled at live-session boundaries or disposal.

History above the latest compaction summary is hidden by default, except for the originals the summary does not cover. The `collapse_compacted_history` preference (settings overlay, or Ctrl+Alt+K) writes `tui.json` and shows the chronological transcript with a dimmed rail when off. Completed summaries expand with Ctrl+Alt+O, one card at a time. A summary that a newer compaction replaced is elided to a placeholder. Missing token estimates are omitted rather than presented as zero.
