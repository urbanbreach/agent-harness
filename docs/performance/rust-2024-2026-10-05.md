# Rust 2024 migration — 2026-10-05

All seven workspace crates use Rust 2024 and Cargo resolver 3. The migration and
modernization pass removes 214 net lines before this report. Dependencies and
`Cargo.lock` are unchanged.

The controlled comparison shows broadly unchanged latency: startup moved from
7.21 to 7.11 ms and a 5,000-fragment stream with durable commit from
19.74 to 20.23 ms. The benchmark also exposed a pre-existing child-journal
leak. Closing writers after terminal receipts keeps the descriptor count at 12
after 256 completed children; the baseline grew from 12 to 524.

Validation is not entirely green. Four PTY assertions, one browser assertion and
five branding findings also fail on the original revision. Details are below.

## Implementation

- Applied let chains across coordinator, provider, tool, CLI and terminal paths.
- Replaced paired `FnMut`/`Future` generics and callback clone wrappers in the
  interactive workflow with `AsyncFnMut` and borrowing async closures.
- Replaced redundant `OnceLock<Mutex<_>>` initialization with constant mutexes and
  two atomic flags. Used `LazyLock` for fixed catalog, syntax and profiling data.
- Used `BTreeMap::extract_if` to remove eval calls, kernel hosts and LSP sessions
  without cloning keys and looking them up again. Existing lock scopes remain.
- Replaced manual UTF-8 boundary scans with `floor_char_boundary` and
  `ceil_char_boundary`; used `is_multiple_of` and `midpoint` where applicable.
- Preserved iterator borrowing contracts with precise `use<...>` captures and
  removed redundant lifetime bounds covered by the 2024 capture rules.
- Preserved selected temporary lifetimes with explicit matches. The compatibility
  pass's remaining drop-order warnings were reviewed before changing editions.
- Replaced process-environment mutation in the terminal failure fixture with a
  filesystem failure after the first session exits. No unsafe block was added.
- Updated edition labels and formatter checks. Formatting uses the 2024 parser
  with the existing 2021 style to keep formatting changes limited. Removed the
  stale Clippy 1.83 setting; the workspace still selects the stable toolchain.

The language and library changes have different compatibility boundaries.
[Let chains](https://doc.rust-lang.org/edition-guide/rust-2024/let-chains.html) and
[automatic lifetime capture](https://doc.rust-lang.org/edition-guide/rust-2024/rpit-lifetime-capture.html)
change with the edition. [Async closures](https://blog.rust-lang.org/2025/02/20/Rust-1.85.0/),
[`LazyLock`](https://doc.rust-lang.org/std/sync/struct.LazyLock.html),
[constant mutex initialization](https://doc.rust-lang.org/std/sync/struct.Mutex.html#method.new),
[`extract_if`](https://doc.rust-lang.org/std/collections/struct.BTreeMap.html#method.extract_if)
and [UTF-8 boundary methods](https://doc.rust-lang.org/std/primitive.str.html#method.floor_char_boundary)
are also usable in edition 2021 with a sufficiently recent compiler. They became
stable after 2021 and simplify these paths. Dynamic tool/provider traits retain
`async-trait` because they require runtime dispatch.

## Measurement method

- Baseline: `414d4d06a75ac186f196c30684e21256ce630b63`. Both revisions use rustc 1.98.0,
  LLVM 22.1.8, the same lockfile, and release optimization level 3, thin LTO,
  one codegen unit and stripped symbols.
- Host: Intel i7-12800H, Linux x86_64, powersave governor. No compiler or other
  task-owned workload ran alongside the timed measurements.
- Saved baseline executables before migrating production code. Their hashes and
  the candidate hashes are in the [JSON report](rust-2024-2026-10-05.json).
- Repaired two stale benchmark drivers for both sides: delegation now uses the
  public `spawn_subagent` contract and checks native child receipts; renderer
  resize commands now run inside an active output frame. The baseline TUI test
  owner was rebuilt with only that fixture repair.
- Initial unpinned measurements varied substantially. An unpinned alternating
  run had stream medians of 19.94 and 31.68 ms; its samples ranged roughly
  19–37 ms. The controlled backend run used CPUs 2 and 4, five processes per
  revision in AB/BA/AB/BA/AB order. The figures below are those medians.
- Eval used the same CPU affinity in ABBA order: 62 warm samples per case after
  warmups, plus 10 cold samples per language. Timings cover JavaScript and Python
  through the public eval session, with immediate host callbacks. Functional
  conformance also covers Ruby and Julia. These timings exclude full coordinator
  and CLI overhead.
- Renderer figures use three separate processes per scenario, 120 measured frames
  per process and unrestricted CPU affinity. Values are medians of run p95s.
  These are measurements on one machine, not confidence intervals or a speedup claim.

The unrestricted 256-child delegation run took

Descriptors at child counts 0, 1, 16, 128 and 256 changed from
**12, 14, 44, 268, 524** to **12, 12, 12, 12, 12**. The old executable still fails
the resource assertion; the new executable passes it. Cancellation completed in
1.42 → 1.71 ms.
The descriptor improvement comes from the journal fix, not the edition itself.

The existing Unicode cursor and output-spill tests were extended; the workflow
error test now exercises async closures borrowing mutable state. The delegation
benchmark is the public regression check for the descriptor leak. No test count
was increased for mechanical syntax changes.

The four PTY failures were reproduced in an isolated checkout of the baseline,
at the same assertions:

- `pty_compaction_stream_animates_resizes_and_cancels` expects the former Esc hint;
  the current UI says Ctrl+C.
- `pty_permission_overlay_resolves_and_preserves_draft` expects the draft to stay
  visible beneath the permission overlay.
- `pty_scroll_follow_requires_second_clamped_page_down` waits for a detached
  indicator with a fixture that fits in the viewport.
- `pty_status_dialog_opens_without_sidebar_copy` expects the former
  “No MCP Servers” dashboard text.

The 80×24 browser smoke case expects “P0-06 canonical” to remain visible under the
command palette. The original Rust 2021 CLI fails the same assertion. Larger
smoke captures, modal chrome, startup reveal, responsive feedback and the ASCII
variant pass. Browser QA requires a clean source tree, so it ran from detached
local snapshot `347e32f5746ed8d9202d72d705965bb4988ae811`; all 164 modified files matched the working patch.

The branding findings are in
`docs/evidence/tui-rewrite/runtime-state/post-measure-host.json:37` and
`plans/001-role-scoped-subagents.md:30,64,65,160`. The one new false positive from
the standard-library midpoint expression was resolved by updating its existing
exact mathematical-expression exemption.

Live-provider signoff, headed native visual signoff and non-Linux targets were
not run. The failed legacy assertions remain visible; this report does not claim
an entirely passing signoff lane.

The eval lane requires Node, Python, Ruby and Julia on PATH. Release binaries were
built only for the CLI and actual benchmark targets; an initial attempt to link
every release test target was cancelled before it ran any tests.

Raw commands, status files, binaries, checksums, measurements, browser evidence
and the implementation patch are retained locally under `target/rust-2024/`.
`measure.py`, `paired.py` and `paired-eval.py` there record the commands used. The
first fast-lane attempt caught formatting and atomic-flag lint issues, which were
fixed; `after/fmt.log`, `after/suite-format.log` and `after/clippy.log` record the
passing final checks. The full nextest result is in
`after/checks/fast/stages/nextest_ci/`.
